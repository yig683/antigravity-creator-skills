# Computer Use (Claude Desktop Parity) Guidelines

- **Execution Hierarchy:** Prefer direct file/shell tools (`read_file`, `write_file`, `run_command`), dedicated connectors, or CDP / `chrome-devtools` / `browser` subagent first for web apps when faster and deterministic. Use the `computer-use` MCP tools for native Windows applications, OS dialogs, visual GUI verification, or logged-in desktop workflows without CDP.
- **Ultra-Fast Action Loop (`flash_lite` Subagent + `batch(fast=true, ui_after=true)` + `paste_text` + `file_dialog`):**
  - Every `screenshot` / `screenshot_after=true` returns an image offloaded to disk, forcing a SECOND LLM turn (`read_file` -> ~8–16s per pair). **Cut turns in half:** set `screenshot_after=false, ui_after=true` on intermediate `batch` calls to receive compact clickable UIA element names & exact coordinates inline as text (zero `read_file` turns!), and request `screenshot_after=true` (with `settle=true`, `marks=true` when visual inspection is needed) ONLY on orientation or final checks.
  - For multi-step desktop GUI loops (2+ visual steps), delegate via `invoke_subagent(TypeName="self", Model="flash_lite", Role="Desktop UI Operator")` for ~1–2s turn latency (escalating to `Model="flash"` only if a step fails or needs complex visual reasoning).
  - Target controls cleanly: `click_element` accepts `name` or `mark_id` and automatically scrolls offscreen UIA matches into view via `ScrollItemPattern`; `type_into` accepts `name`, `mark_id`, `coordinate`, or `x`+`y` (with `paste="auto"` clipboard acceleration); `paste_text` sets clipboard + clears + pastes (`Ctrl+V`) in ONE batch step (never spend separate `clipboard_set` turns!); `file_dialog` completes Windows `#32770` Open/Aç dialogs in ONE batch step; standalone mouse tools (`left_click`, `right_click`, `middle_click`, `double_click`, `triple_click`, `mouse_move`, `left_mouse_down`, `left_mouse_up`, `scroll`) accept `mark_id`, `x` + `y`, `name`, `coordinate`, `marks`, and `settle`; `left_click_drag` accepts `from_mark_id`/`to_mark_id` (`start_mark_id`/`end_mark_id`), `start_coordinate`/`end_coordinate`, `x`/`y`, or `name`.
  - Chain as many deterministic actions as possible into ONE `batch(..., fast=true)` call (`fast=true` executes pointer hops instantaneously without 220ms glide sleeps). Valid `batch` step formats include `{"action": "click_element", "mark_id": 30}`, `{"type": "click", "x": 400, "y": 250}`, or shorthand `{"click_element": {"mark_id": 30}}`, `{"paste_text": {"name": "Title", "text": "..."}}`, `{"file_dialog": "C:\\path\\file.mp4"}`, plus aliases (`click`, `move`, `hotkey`/`press_key`, `sleep`, `drag`, `paste`, `fill`, `select_file`). Never call duplicate `screenshot` after `screenshot_after=true` or add visibility delays.
- **Anti-Loop & Offscreen Recovery:**
  - Never issue targetless clicks without a preceding `mouse_move`, and never repeat the same click coordinate/mark 3+ times without visual change: the server blocks the 3rd stationary click (`ok: false, loop_detected: true`) and returns a fresh `marks=true` screenshot.
  - `click_element` / `type_into` auto-scrolls offscreen UIA controls via `ScrollItemPattern` when supported; if a UIA lookup still reports offscreen matches (`Found N offscreen match(es)`), scroll once or inspect the returned `ui_after` / `marks=true` frame before retrying.
- **Coordinate System:** Pass `[x, y]` in the active `screenshot` coordinate space (matching the latest captured `display_number`).
- **Safety & Privacy:** Never attempt to click through UAC prompts, lock screens, or password managers. Do not interact with sensitive personal, financial, or unrequested apps without calling `request_access` or asking the user first, and mark password/secret inputs with `sensitive=true`.
